# Scripted MCP Protocol Walkthrough

> ⚠️ **Note:** This is a scripted walkthrough of the MCP protocol. The agent turns are written by the test harness script, not generated by an LLM. It demonstrates the exact JSON-RPC request and response payload exchange between an MCP client and Conflict Radar over stdio.

---

### **System**

Conflict Radar MCP Server initialized over stdio protocol.

### **User Instruction**

Please refactor `normalize()` in `utils.py` to strip leading and trailing whitespace. Ensure you coordinate with other agents using Conflict Radar MCP before making any changes.

### **Agent Workflow (narration)**

Before modifying `utils.py::normalize`, the agent consults Conflict Radar via the `claim` MCP tool to verify whether any concurrent agents are touching dependent symbols.

### **Agent Client -> MCP Request**

**Tool:** `claim`
```json
{
  "agent_id": "test-dev-agent",
  "symbol_id": "utils.py::normalize",
  "change_type": "BODY"
}
```

### **Conflict Radar -> MCP Response**

```json
{
  "verdict": "BLOCK",
  "claim_id": "claim_5d5dde",
  "conflicting_claim_id": "claim_8ff03a",
  "path": [
    "handler.py::parse_request",
    "validator.py::validate_input",
    "utils.py::normalize"
  ],
  "hops": 2,
  "reason": "Dependency conflict (2 hops): Agent 'test-dev-agent' (BODY) and Agent 'upstream-agent' (SIGNATURE) along call path handler.py::parse_request -> validator.py::validate_input -> utils.py::normalize.",
  "precedent_count": 0,
  "last_collision_time": null
}
```

### **Agent State Transition (narration)**

Conflict Radar returned a **BLOCK** verdict. An active lock is held upstream on `handler.py::parse_request` (claim ID `claim_8ff03a`). Modifying `utils.py::normalize` now would risk breaking an in-flight caller contract. The agent enters a `WAITING` state and polls `check()` until the upstream lock clears.

### **Agent Client -> MCP Request**

**Tool:** `check`
```json
{
  "claim_id": "claim_5d5dde"
}
```

### **Conflict Radar -> MCP Response**

```json
{
  "claim_id": "claim_5d5dde",
  "agent_id": "test-dev-agent",
  "symbol_id": "utils.py::normalize",
  "change_type": "BODY",
  "status": "waiting",
  "blocked_by": "claim_8ff03a"
}
```

### **Harness Event (Upstream Release)**

`upstream-agent` finishes its code changes and calls `release` on `claim_8ff03a`.
FalkorDB atomically removes the `BLOCKED_BY` relationship and promotes the waiting claim to `active`:
```json
[
  {
    "claim_id": "claim_5d5dde",
    "agent_id": "test-dev-agent",
    "symbol_id": "utils.py::normalize",
    "new_status": "active",
    "verdict": "SAFE"
  }
]
```

### **Agent Client -> MCP Request**

**Tool:** `check`
```json
{
  "claim_id": "claim_5d5dde"
}
```

### **Conflict Radar -> MCP Response**

```json
{
  "claim_id": "claim_5d5dde",
  "agent_id": "test-dev-agent",
  "symbol_id": "utils.py::normalize",
  "change_type": "BODY",
  "status": "active"
}
```

### **Agent Action (narration)**

Status has been promoted to **ACTIVE** (`blocked_by: null`). It is now safe to apply code edits without conflicting with peers.

```python
# utils.py
def normalize(text: str) -> str:
    return text.strip().lower()
```

### **Agent Client -> MCP Request**

**Tool:** `release`
```json
{
  "claim_id": "claim_5d5dde"
}
```

### **Conflict Radar -> MCP Response**

```json
{
  "status": "released",
  "claim_id": "claim_5d5dde",
  "unblocked_claims": []
}
```

### **Agent Response (narration)**

Refactoring of `normalize()` in `utils.py` complete. Coordinated via Conflict Radar: initially waited for an upstream signature lock on `handler.py::parse_request` to clear, acquired an active lock upon release, applied edits safely, and released the lock.
